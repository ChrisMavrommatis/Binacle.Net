## Two configuration pages are new in v3.0.x

Neither has a `v2.1.x` equivalent to copy.

- [ ] **`configuration/core/forwarded-headers.md`** - running behind a proxy or CDN. Source of truth is the API
      configuration doc. Needs: the trust settings, the container and tunnel cases, using `/_debug` to read what
      the proxy is sending, the vendor header names (`CF-Connecting-IP`, `X-Real-IP`, `X-Azure-ClientIP`), and
      why `ASPNETCORE_FORWARDEDHEADERS_ENABLED` is ignored (it enables the middleware with no proxy
      verification, which lets any caller choose their own address). Also:
      - `TrustedProxies` entries are read exactly as written, the same rule as `RestrictedIPs` below. Point at
        that section rather than repeating the table.
      - **The app warns once in the log** when a forwarding header arrives and does not take effect - either the
        feature is off, or the trust list does not name the proxy. Tell the reader to look there first; it is
        cheaper than turning on `/_debug`, which echoes their own `Authorization` header back.
- [ ] **`configuration/diagnostics-module/health-checks.md`** - carry the page over from `v2.1.x`, then document
      the four breaking `RestrictedIPs` changes:
      - CIDR now means a prefix length. The value after `/` was read as an address mask, so `192.168.1.0/24`
        matched nearly the whole IPv4 range. Existing entries are now **much narrower** - re-check who is inside
        one or risk locking yourself out.
      - IPv4 callers arriving in IPv4-mapped IPv6 form are unmapped before matching, so the list works in a
        container at all. It previously could match no IPv4 entry.
      - The `start-end` range form is removed and now fails startup validation.
      - **Entries are read exactly as written** (added 2026-07-27). An IPv4 address must be four plain decimal
        parts: `010.10.10.10` used to be read as octal and admit `8.10.10.10`, `10.1` used to mean `10.0.0.1`,
        and `167772161` meant the same. IPv6 must be in the short lowercase form, so `2001:0DB8::1` becomes
        `2001:db8::1`. All of these now fail startup validation. Worth a short "check your existing list" box:
        the failure mode was admitting a host nobody named, so an operator should look at what their old entry
        actually matched.
      - Not breaking, but explain it: `192.168.1.1/24` means the whole `192.168.1.0/24` block, 256 addresses.
        That is what CIDR notation means everywhere and it is accepted, and the app logs what the entry
        resolved to at startup.
      - Behind a proxy the list needs forwarded headers enabled, or it is compared against the proxy's address
        and can never match.
